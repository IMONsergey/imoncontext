# Правила для ИИ-агентов

Этот репозиторий — источник корпоративного контекста IMON. Он используется для подготовки сайтов, презентаций, коммерческих предложений, кейсов, публикаций, писем, сценариев, промптов и внутренних документов.

## Обязательный порядок работы

Перед задачей, связанной с IMON:

1. Прочитать `context/core.md`.
2. Прочитать релевантный предметный файл.
3. Проверить `context/decisions.md` на актуальные решения и открытые противоречия.
4. Для текстов обязательно применить `context/tone-of-voice.md`.
5. Для автоматической обработки использовать `data/company.yaml`, но при расхождении считать Markdown-файлы приоритетными.

## Нельзя

- Называть IMON «веб-студией», «креативным агентством» или «digital-агентством полного цикла» как основным самоопределением.
- Сводить описание компании к перечню услуг.
- Придумывать клиентов, цифры, результаты, награды, сроки работы или масштаб команды.
- Обещать рост продаж, «взрыв рынка», гарантированный результат или иные недоказуемые эффекты.
- Использовать рекламный шум: «вау», «топовый», «уникальный», «прорывной», «продающий», «быстро и недорого».
- Молча выбирать одну из конфликтующих формулировок. Неопределённость должна быть обозначена.
- Представлять рабочую гипотезу как утверждённый публичный слоган или стратегию.

## Базовая логика ответа

Для описания задачи использовать последовательность:

`бизнес-ситуация → разрыв или проблема → системное решение → роль IMON → изменение для бизнеса`

Услуги и носители появляются после объяснения задачи. Сайт, презентация, айдентика и digital — инструменты внутри более широкой системы бренда и коммуникации.

## Стиль

- Спокойный, точный, структурный, уверенный, понятный и честный.
- Один абзац — одна мысль.
- Одно предложение — один смысловой шаг.
- Профессиональная лексика без терминологического тумана.
- Причинно-следственные связи вместо деклараций.
- Внешний эффект описывать через ясность, доверие, восприятие, соответствие масштабу и управляемость коммуникации.

## Работа с фактами

Каждое утверждение должно иметь один из статусов:

- `confirmed` — подтверждено источником или прямым решением;
- `working` — рабочая формулировка или гипотеза;
- `open` — вопрос не решён;
- `deprecated` — старое описание, которое хранится только для истории.

Если факт может устареть — указывать дату актуальности.

## Изменение репозитория

При содержательном обновлении:

1. Изменить профильный файл.
2. При необходимости обновить `context/core.md`.
3. Зафиксировать решение или конфликт в `context/decisions.md`.
4. Синхронизировать `data/company.yaml`.
5. Добавить запись в `CHANGELOG.md`.

Не создавать несколько почти одинаковых файлов. Новая сущность должна иметь понятного владельца и назначение.
